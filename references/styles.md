# Video Edit — styles and the Style Picker

Every edit is built once, in Warm Paper, then shown in **nine styles** side by side. The creator picks one; only that
one is rendered. A style changes the look only: ground, colours, type, cards, captions and texture. The cut, the words
and their timing, the B-roll, the face panel, the motion and the sound stay exactly as built.

| id | Style | Look | Good for |
| --- | --- | --- | --- |
| `paper` | A · Warm Paper | the original: cream paper, grain, window-light leaves, serif italic, teal | calm tutorials, AI tools, personal finance |
| `glow` | B · Midnight Glow | near-black, cyan and violet light, faint grid, glassy cards, Outfit | tech, AI, data |
| `doodle` | C · Storybook Doodle | notebook paper, ruled lines, red margin, hand-drawn outlines, Caveat + Nunito | beginners, light topics |
| `editorial` | D · Bold Editorial | newsprint, halftone corners, black rules, uppercase League Gothic, black caption bars | news, hot takes, markets |
| `block` | E · Colour Block | a flat colour per scene (blue, bone, black, lime, vermilion), uppercase Anton | hooks, punchy lessons, money tips |
| `riso` | F · Riso Print | ultramarine + fluorescent pink, grainy paper, halftone discs, Bodoni Moda | stories, data |
| `terminal` | G · Signal Terminal | black screen, scanlines, lime, all JetBrains Mono, outlined panels | tech, coding, how-to |
| `sticker` | H · Sticker Board | cream board, dot grid, thick black outlines, hard shadows, Bricolage Grotesque | step-by-step explainers |
| `aurora` | I · Aurora | pale cool ground, lavender/peach/mint light, dot grid, glass cards, serif italic | apps, AI tools, calm modern |

`python <SK>/scripts/styles.py list` prints the same list.

## Files
```
<P>/styles/<id>/                full HyperFrames project per style (render it like the main one)
   compositions/, index.html    generated by styles.py from the edit; every build overwrites them, never edit by hand
   assets -> ../../assets       a link, so the footage is never copied
   check.log, snapshots/        written by `check` and `snap`
<P>/styles/styles.json          what was built, the edit's duration
<P>/styles/pick.json            the creator's pick (written by the picker's button or `styles.py pick`)
<P>/styles/sheet.jpg            every style at the same 5 moments, one image
<P>/picker.html                 the Style Picker (open it through `styles.py serve`, not as a file)
<P>/build/style-overrides/<id>.css   per-video fixes for one style (the only place to fix a style)
```

## Commands
```bash
python <SK>/scripts/styles.py build <P>                      # all nine styles + picker.html (seconds)
python <SK>/scripts/styles.py build <P> --styles glow        # one style again, after a fix
python <SK>/scripts/styles.py check <P> --styles glow,block  # hyperframes lint + check per style (~2 min each)
python <SK>/scripts/styles.py snap  <P> --styles glow        # one frame per scene -> styles/glow/snapshots/
python <SK>/scripts/styles.py sheet <P>                      # all styles, 5 moments -> styles/sheet.jpg (~1 min)
python <SK>/scripts/styles.py serve <P> [--port 8770]        # the picker at http://127.0.0.1:8770/picker.html
python <SK>/scripts/styles.py pick  <P> [glow]               # record / print the pick
```
`snap` and `sheet` take `--at 12.5,30,48` for chosen moments; the default is one moment late in each scene.

## How a style is applied (so you know what a fix has to beat)
- **Colours.** Every warm neutral of the kit (paper, ink, greys, borders) moves onto the style's ground and ink with the
  contrast it had on paper, so text that passed the WCAG check still passes. The teal family becomes the style's accent;
  an accent the creator chose with `finish(accent=…)` is not teal and carries into every style unchanged. Warm shadows
  take the style's shadow colour. Real colours (a green gain, a red loss, a yellow highlight) stay. Caption text on
  footage (`#FFF8EF`) stays.
- **Type.** Instrument Serif / Instrument Sans / JetBrains Mono point at the style's fonts under names of their own
  (`ve-<id>-serif`…), scaled with `size-adjust` so a line keeps its width.
- **Look.** The style's CSS: the ground's decor on `.bx-paper` and its `::before` / `::after`, card treatment on the
  kit's surfaces (`.bx-card`, `.doc`, `.pf`, `.ckl`, `.pr-tile`, `.bx-browser`…), captions on `.pl`.
- **Colour Block** gives each scene, in timeline order, the next ground of five (blue, bone, black, lime, vermilion).

## Fixing a style for one video
Write CSS in `<P>/build/style-overrides/<id>.css`, then `styles.py build <P> --styles <id>` and `snap` again. The file is
added last to every composition of that style, so scope each rule. Every scene's root is `#sNN-root` and every id in
it starts with `sNN-`.

| Problem in the frames | Fix |
| --- | --- |
| A word or line runs off the canvas (an uppercase style or a wider font) | `#s07-root .bx-serif{font-size:.9em}` or a smaller `font-size` on that id |
| Text or a card vanishes into the ground (a hard-coded white or rgba the palette doesn't map) | `#s05-card{background:#141C33}` / `#s05-k{color:#EEF1FA}` with the style's card / ink |
| Decor over the face or over text | `#s12-root .bx-paper::before{display:none}` (or `::after`) |
| A caption hard to read on its footage | `#s09-root .pl{background:#111;color:#fff}` |
| A product colour clashes with the ground | give that element a card behind it: `#s04-logo{background:#fff;border-radius:16px;padding:12px}` |

Never change words, timing, footage, motion or sound in a style; a fix that needs more than CSS goes back to
`build/scenes.py` (then build all styles again).

## The check workflow
`<SK>/workflows/check-styles.js` runs one agent per style (except Warm Paper, which is the edit you already checked):
lint + check, frames compared with Warm Paper at the same moments, fixes in the style's override file, at most a few
rounds each. It returns which styles are ready and which need attention:
```
Workflow  scriptPath: <SK>/workflows/check-styles.js
          args: {"project": "<P>", "skill": "<SK>"}          # optional: "styles": ["glow","block"], "times": [...]
```
Installed as a plugin, it is also listed as `video-edit:check-styles`. Without the Workflow tool, do the same by hand:
`styles.py check <P>` then `styles.py snap <P>` and read every `styles/<id>/snapshots/contact-sheet*.jpg` (a long edit gets several).

## The picker
`styles.py serve <P>` (in the background) serves `picker.html` with byte ranges, so every style plays and seeks. All
styles play in sync and muted except the selected one; "Play only the selected style" helps a slower computer. "Use this
style" writes `styles/pick.json`; the creator can also just say which one. In Claude Code's desktop app open the URL in
the Browser pane; anywhere else give the creator the URL (it works in any browser on the same computer while `serve`
runs). Always also send `styles/sheet.jpg`, which needs no server.

## Rendering the pick
The commands of `pipeline.md` §7, run from `<P>` with the style folder as the project and an absolute output, so the
renders still land in `<P>/renders/`:
```bash
npx --yes hyperframes@0.8.106 render styles/<pick> --fps 30 --quality delivery --crf 14 --output "$PWD/renders/<slug>_master.mp4"
```
(2K: the same `--resolution portrait-4k` render + downsample as §7.) Then the same verify steps (`verify_render.py`,
`sync_check.py`) and deliver `<name> (Edited).mp4`. When the creator wants more than one style ("render all", "B and
E"), render each from its own folder to `renders/<slug>_<id>_master.mp4` and deliver `<name> (Edited, <Style>).mp4`;
they render one after another (each render already uses every core).
